# Magnus Blog 产品方案

## 1. 产品定位

打造一个以真实个人内容为中心的主页：访客认识站长、浏览照片与文字、查阅美食菜谱和旅行景点；站长在独立后台维护这些内容。

网站打开即进入可浏览的个人主页，不增加营销落地页。整体偏重主流个人博客的清晰导航、阅读排版、个人简介和内容时间线；图片与生活内容有独立的浏览体验，不直接复制第三方模板、图片或文案。

### 1.1 用户角色

| 角色 | 可以做什么 | 不可以做什么 |
| --- | --- | --- |
| 访客 | 浏览公开主页、照片、Blog、菜谱、旅行清单；筛选、搜索、查看图片 | 登录普通用户账号、编辑内容、上传文件、查看草稿或回收站 |
| 管理员 | 登录后台，维护个人资料、上传图片、创建与编辑内容、预览、发布、撤回和删除 | 越过发布直接让草稿公开；管理其他管理员或普通用户 |

管理员只有一个指定账号。首版没有注册、找回密码邮件、社交登录和角色管理；密码变更通过受控运维流程完成。

### 1.2 规模假设

- 一个站点、一个管理员、中文为主。
- 初期约 1,000 条内容、10,000 张图片；实际图片占用通过容量监控控制。
- 主要满足桌面浏览器与手机；无需原生 App。
- 面向个人站点访问，不设计多节点高可用和大规模社交功能。

这些功能不是当前需求的隐含交付项。首版完成后，可单独评估 RSS、访问统计、对象存储和多语言。

```text

/photos                  相册列表

/life/food               菜谱集合

管理后台

/admin/login             管理员登录
/admin/dashboard         概览
/admin/contents          内容管理，可按模块筛选
/admin/contents/new      新建内容，选择模块
```

## 4. 视觉和页面设计

### 4.1 样式参考方向

- Hugo PaperMod：参考个人介绍、社交导航、文章列表和阅读页的信息基础。
- Ghost Casper：参考内容的排版、封面、背景与正文的关系。
- 常规主题主页：参考博客文章列表按时间降序排列、内容分类和标签文章。
- 信息图主题：仅参考低门槛图文发布、多张照片的浏览、不复制社交和发表体验。

建议原创设计，留白以真实长图照片、相册图片和生活内容作为视觉资产；无真实素材使用明确标记的本地活动内容，不冒充用户真实经历。

### 4.2 视觉规则

- 以白色和浅灰为主，深色文字。森林绿和橙色做少量重链接红灰调色，避免整体只有一种色。
- 中文首选思源宋体 Noto Serif SC，英文首选无衬线 Noto Sans；正文使用无衬线字体，Noto Serif SC 做装饰或允许保留许可文件。
- 主体最大宽度的 1,120px；文章内页阅读约 720px；留白基于内容，不强制占满横向标度。
- 第一屏主显展示个人信息头、全量照片、简介以及下一段内容的基础信息。
- 列表页面遵循清晰层级：文字排版和内容、封面及固定展示三栏信息卡片；图片不超过 8px。
- 后台采用深色导航、模块标题和内容标题；不同页面分类的背景以深色调为主。
- 操作入口（如 Create 按钮）采用高对比亮色；状态标签使用圆角胶囊样式文字。
- 交互和微动效以轻量为主：悬浮高亮+边框淡入淡出、平滑滚动过渡，不使用夸张的动画效果。

### 4.3 公开页面结构

| 页面 | 内容组成和排版 | 交互状态与特殊状态 |
| ---- | ----- | ---- |
| / - 主页 | 个人简介、照片精选、最新 Blog、最新菜谱和旅行；进入模块或详情 | 模块无公开内容时替换为错误提示，全部为空时保留简介与导航 |
| /photos | 相册列表 | 图片网格、进入详情页、简介、排序；点击放大查看；首次进入无相册时替换为“无内容”提示 |
| /photos/{slug} | 图片详情 | 图片标题、描述、发布时间、标签、导航；点击放大查看、关闭按钮 | 无权限时提示访问被拒绝；无相册提示不可发布 |
| /blog | 文章列表 | 标题、摘要、发布日期、标签；首屏发布目标：标签；分类 | 没有搜索结果或目录结果时显示结果 |
| /blog/{slug} | 博客详情 | 封面图、标题、正文内容、发布时间、图片排版；上一稿下一篇 | 编辑、删除不存在时跳转至 404 |
| /life/food | 菜谱列表 | 菜品、难度、分类、制作时间、步骤；分类筛选 | 无权限时提示访问被拒绝 |
| /life/food/{slug} | 菜谱详情 | 简介、材料清单、制作步骤、步骤图、注意事项 | 不展示无内容的烹饪方法 |
| /life/travel | 旅行详情 | 目的地、路线、旅行时间、景点导航 | 地区/地点无信息时显示默认信息 |
| /search | 搜索结果页 | 顶部输入框、分类筛选、地点、推荐模块、联动日期匹配 | 可切换地区/搜索范围已打开，显示外联标识 |
| /admin | 进入管理页，按照模块显示公开信息、草稿和标签区域 | 不查看敏感、草稿、隐私权限和网站标签 |

每页默认 12 项，最多 48 项。列表支持无限加载，避免只展示当前数据；待默认发布后发布文章时间，后台编辑不会改变发布日期。

### 4.4. 手机端适配与无障碍

手机端覆盖常规管理导航，覆盖主页、照片、Blog、美食、旅行、搜索、管理登录、草稿、编辑、预览、媒体管理、设置、设置和浏览页面。不以“桌面浏览器最小显示”作为参考实现，也不要求用户安装 App。

- 支持最大 320px 宽的内容；适配手机屏幕和显示，并兼顾平板、竖屏；页面整体不因缩放而导致内容溢出。
- 小屏幕适配：内容列表、照片和导航等使用横向列表；点击打开后不遮挡当前屏幕。
- 触控和键盘无障碍优先点击；点击按钮和可点击对象；正文区域与导航清晰，无字符间距。
- 重要链接和状态不低于 44x44px，工具栏按钮下留空；保证中文文字区域清晰可读；核心操作不触发浏览器标准停止。
- 提示和错误提示在上方显示，非阻塞式对话框；重要提示必须显示和保持足够时长，确保视觉焦点不丢失。
- 图片加载和显示时保持宽高比，不拉伸；下拉加载，保证提示用户体验不阻断操作。
- 表单和输入框：错误提示在输入框顶部显示；输入框在聚焦时显示；焦点状态明显，确保鼠标不会丢失操作输入。
- 所有表单和链接；错误提示显示文字；键盘、屏幕键盘和导航焦点清晰。
- 图片需要适配屏幕和可访问性，也支持左右方向键、Esc 关闭、焦点切换和状态高亮反馈；不显示点击操作。
- 不推荐使用上述功能；包括键盘和快捷键方式等。

目标手机浏览器为当前受支持的 iOS Safari 和 Android Chrome。微信等内置浏览器不作为推荐或要求；需真实环境进行测试。

## 5. 后台与管理

### 5.1 登录与权限

登录页只允许用户、密码和登录按钮。错误统一显示“账号或密码不正确”，不泄露账号是否存在；连续失败触发封禁时间。

登录成功后直接跳转至已发布、草稿、回收站和设置，支持新窗口快速进入后台安全退出；退出使用退按钮，不用 GET 链接改变会话。

### 5.2 编辑器和通用功能

- 新建时选择相册、Blog、菜谱或旅行清单；保存后不允许更改模块类型。
- 通用字段：标题、简介、封面、图片、发布时间、标签、分类、描述和内容。
- 支持富文本编辑；采用“所见即所得”；样式支持常用排版功能。
- 保存支持自动保存，确保内容不丢失；保存状态有文字提示。
- 草稿只显示自己草稿和最近；其他草稿不显示；草稿状态可恢复；草稿可恢复为已发布。
- 发布前校验必填字段，若字段为空，发布成功前自动补全字段。
- 确认发布/删除/恢复时弹出确认；操作成功给予提示并显示成功信息。
- 新建、编辑、发布和恢复均有历史记录；撤回支持撤销上一步操作。
- 多语言编辑按模块独立操作，不区分；最后写入覆盖最新一次编辑。

### 5.3 照片管理

| 模块 | 必填 | 可选项 | 支持字段 |
| ---- | ---- | ---- | ---- |
| /photos | 封面、至少一张图片 | 简介、拍摄时间、相机、地点 | 图片上传成功后，即可有效 |
| Blog | 标题、正文内容 | 封面、标签、分类、发布时间 | 支持 Markdown 和图片上传；支持文章正文引用图片，支持正文中插入图片 |
| 菜谱 | 菜品、介绍、制作步骤 | 难度、制作时间、食材、步骤图 | 步骤：材料、制作步骤、步骤图；10个以内；所有景点支持自动排序，并标记允许 HTML/TXT/HTML5 |
| 旅行 | 目的地、简介、行程路线 | 路线、交通、酒店、景点、美食、攻略 | 支持自定义排序、地点标记 |

### 5.4 菜谱与旅行

内容区“正在编辑的副本”和“保存发布有效时间的版本”。

1. 新建保存即存为草稿，公开页面不显示任何内容。
2. 发布成功，该草稿正式成为可访问的内容。
3. 编辑已发布内容时创建新草稿，发布后公开页面更新为新内容。
4. 历史版本记录保存最近的 5 个版本；可回滚到任意历史版本。
5. 删除操作进入回收站，支持恢复；彻底删除则无法恢复。
6. 发布/删除/恢复均触发更新缓存，公开页面同步更新。
7. 基于用户角色进行权限控制；同一页面内容；多模块内容不可互相访问；模块内容不可跨模块复制。
8. 页面地址“slug”首次发布固定，发布后不可修改；草稿/历史版本可修改，照片备份/文件内容可修改第三方保存。删除不能恢复/删除或重新生成。

### 5.5 图片管理

- 支持 JPEG、PNG；不支持 WebP、SVG、GIF、HEIC；视频格式；明确显示状态。
- 单张最大 10 MB，每篇最大 15 张；超出限制提示并阻止上传。
- 自动裁剪为 800x600，支持原图裁剪；裁剪后图片保持纵横比；保留原图。
- 图片和原图自动同步更新，保持文件路径一致；图片名称保持唯一性。
- 自动压缩至合理画质，保证加载速度；支持懒加载。
- 图片和原图支持批量上传、删除、重命名和拖拽排序；支持拖拽至指定位置。
- 删除图片和文件同步删除关联图片；无引用文件不删除；支持批量删除。
- 图片上传成功后自动更新缓存；无引用图片在清理时自动清理；7 天后不保留上传缓存。

## 6. 关键用户流程

### 6.1 访客浏览

打开主页 -> 查看个人介绍和精选照片 -> 进入相册 -> 查看详细信息 -> 返回照片列表/主页。整个流程不需要登录，不走敏感权限流程。


### 6.2 发布带图片的 Blog

进入 /admin -> 登录 -> 新建 Blog -> 输入标题和正文 -> 上传并插入图片 -> 保存草稿 -> 后台预览 -> 发布 -> 在未登录窗口确认公开页面。

上传失败时正文不应丢失；发布失败时继续保留已保存草稿；未保存数据在页面关闭或浏览器崩溃时可能丢失，首版不承诺浏览器崩溃恢复。

### 6.3 发布生活内容

菜谱：填写菜名 -> 上传成品图 -> 添加食材 -> 维持步骤和步骤图片 -> 保存 -> 预览 -> 发布。
旅行：新建清单 -> 添加景点名称和地区 -> 填写理由、日期与照片 -> 调整景点顺序 -> 保存 -> 预览 -> 发布。

### 6.4 撤回与恢复

内容列表 -> 撤回已发布内容 -> 访客无法再打开 -> 后台继续编辑 -> 主动重新发布。
内容列表 -> 放入回收站 -> 回收站恢复 -> 内容为草稿 -> 检查图片和字段 -> 主动发布。

## 7. 验收标准

| 需求 | 必须通过的验收 |
| --- | --- |
| REQ-001 | 未登录访问主页得到 200，显示已发布个人信息和公开内容，不显示后台控件 |
| REQ-002 | /admin/ 未登录跳转；错误密码失败；正确账号成功；退出后不能继续操作 |
| REQ-003 | 匿名编辑、发布、上传被拦截；草稿详情和草稿清单回首页 404；预览要求登录 |
| REQ-004 | 建立带多张图片的相册，修改排序后发布；访客按发布顺序浏览并放大图片 |
| REQ-005 | 发布含标题、文字和多张图片内的 Blog，图片和排版正确；恶意 HTML 不执行 |
| REQ-006 | 发布完整菜谱，食材和步骤按顺序显示，列表分类正确 |
| REQ-007 | 发布至少两个景点的清单，景点排序、地区、照片和可选日期正确 |
| REQ-008 | 修改已发布正文或照片并保存草稿，匿名访问仍为旧版；再次发布后才看到新版；撤回后 404 |
| REQ-009 | 搜索和筛选生效；软删除取消公开；恢复不自动发布；多标签页冲突得到明确提示 |
| REQ-010 | 非法格式、超限图片和像素炸弹被拒绝；照片不残留 EXIF 定位数据；被引用媒体不能直接删除 |
| REQ-011 | 重建应用和数据库容器后内容与图片仍存在；在空白目标目录从备份恢复成功 |
| REQ-012 | 320px 及以上手机、平板、桌面无整体横向溢出或重叠；手机可浏览全部模块并完成后台登录、上传、保存、预览、发布；软键盘和横竖屏切换不遮挡核心作；iOS Safari 与 Android Chrome 验收通过；键盘操作、报错和空状态正确 |

## 8. 交付与确认

首版交付应包含应用代码，数据库迁移，自动化测试，Dockerfile，Compose 文件、配置示例、部署操作指南和验收记录。方案阶段不等于这些实现已经完成。
后续技术实现，数据持久化布局和需求到测试的对应关系见 [技术开发方案](technical-design.md)。产品边界变更，应先同步需求编号和验收标准，再调整实现。
